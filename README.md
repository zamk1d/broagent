# broagent

Автономный AI-агент, который управляет реальным браузером (Playwright/Chromium)
для выполнения произвольных многошаговых задач — без захардкоженных селекторов,
URL или сценариев. Работает через Anthropic (Claude, с vision) или Groq
(текстовые модели OpenAI-совместимого API).

## Установка

```bash
pip install -e .
playwright install chromium
cp .env.example .env   # и впиши ключ нужного провайдера
```

## Настройка (.env)

| Переменная                | По умолчанию                   | Что делает                                              |
|---------------------------|--------------------------------|---------------------------------------------------------|
| `BROAGENT_PROVIDER`       | `anthropic`                    | `anthropic` или `groq`                                  |
| `ANTHROPIC_API_KEY`       | —                              | ключ Anthropic (обязателен при `provider=anthropic`)     |
| `ANTHROPIC_MODEL`         | `claude-sonnet-5`              | модель Anthropic                                        |
| `GROQ_API_KEY`            | —                              | ключ Groq (обязателен при `provider=groq`)               |
| `GROQ_BASE_URL`           | `https://api.groq.com/openai/v1` | OpenAI-совместимый endpoint Groq                       |
| `GROQ_MODEL`              | `llama-3.3-70b-versatile`      | модель Groq                                             |
| `BROAGENT_PROFILE_DIR`    | `./profile`                    | каталог persistent-профиля Chromium                     |
| `BROAGENT_START_URL`      | `about:blank`                  | стартовая страница                                      |
| `BROAGENT_MAX_STEPS`      | `30`                           | лимит шагов на одну задачу                              |
| `BROAGENT_MAX_TOKENS`     | `2048`                         | лимит токенов ответа модели                             |

## Запуск

```bash
broagent
```

Открывается видимый браузер (persistent-профиль — можно один раз войти в аккаунты
руками, дальше сессия сохраняется) и интерактивный чат в терминале:

```
› найди самый дешёвый рейс Москва — Питер на завтра на Авиасейлс
```

Агент печатает каждый вызов инструмента и его результат по мере выполнения, в
конце — итог. После этого можно сразу вводить следующую задачу: агент помнит
контекст предыдущей, `/new` — сбросить историю.

Команды чата: `/help`, `/url`, `/new`, `/exit`.
Ctrl+C во время работы прерывает текущую задачу, браузер остаётся открытым.

## Архитектура

### Управление браузером

- **`browser/session.py`** — persistent-контекст Chromium. Отслеживает активную
  вкладку динамически (клик может открыть попап/новую вкладку — сессия сама
  переключается на неё), обрабатывает JS-диалоги (`alert`/`confirm` dismiss,
  `beforeunload` accept). Инструменты всегда берут `page` через `session.page`,
  не кэшируют ссылку.
- **`page_control/collector.py`** — вытаскивает из DOM только видимые
  интерактивные элементы (`a, button, input, textarea, select, [role=button],
  [contenteditable]`), проставляя им временный `data-agent-id`. Проверяет
  перекрытие через `elementFromPoint` — то, что физически нельзя кликнуть
  (например, под модалкой), в список не попадает. Дополнительно умеет:
  - **регионы** (`list_regions` через `data-agent-region`) — крупные
    landmark-блоки страницы с количеством элементов в каждом;
  - **чтение текста** (`read_text`) целиком по странице или региону;
  - **ARIA-алерты** (`read_alerts`) — `role="alert"`, `aria-live`, `aria-invalid`;
  - **текст открытого диалога** (`read_dialog_text`) — самый крупный
    `[role=dialog]/[aria-modal]/<dialog>`.
  - При пустом результате сразу после навигации делает повторную попытку через
    0.9 c — лечит частую SPA-гонку.
- **`page_control/actions.py`** — `click` / `type_text` / `select_option` /
  `goto` / `go_back` / `scroll_page` / `wait` / `current_url`. Каждое действие
  дожидается `domcontentloaded`, а клики и submit-ввод автоматически
  дописывают к результату текущие ARIA-алерты («⚠ страница показывает: …»),
  чтобы модель видела валидационные ошибки, не вызывая лишних инструментов.

### Инструменты

- **`tools/schemas.py`** — описание инструментов в формате Anthropic tool-use.
  Набор:
  `goto`, `go_back`, `list_regions`, `list_elements`, `read_text`, `click`,
  `type_text`, `select_option`, `scroll_page`, `wait`, `current_url`,
  `ask_user`, `ask_page`, `finish`.
- **`tools/dispatcher.py`** — исполняет вызовы, держит `_last_elements` (чтобы
  по `element_id` найти текст элемента для проверки на опасность) и сбрасывает
  его после любого действия, меняющего DOM. Прогоняет через слой безопасности
  перед `click`/`type_text`. `ask_page` делегирует саб-агенту
  (`agent/subagent.py`).

### LLM-клиент

- **`agent/llm_client.py`** — единый фасад `ask_model(system, messages, tools)`
  с синглтоном клиента. Внутри:
  - **Anthropic** — нативный SDK, конвертация блоков как есть, retry с
    backoff на `RateLimitError`/`APIStatusError`/`APIConnectionError`.
  - **Groq** — OpenAI-совместимый клиент. Канонический формат сообщений
    транслируется в OpenAI-формат (`_canonical_to_openai`,
    `_openai_message_to_blocks`), инструменты — в `{"type": "function", …}`.

### Основной цикл

- **`agent/loop.py`** — цикл tool-use:
  1. `_truncate_old_tool_results` обрезает тела старых `tool_result` (кроме
     последних `MAX_TOOL_RESULT_HISTORY = 4`) до `TRUNCATE_AT = 700` символов,
     чтобы длинные задачи не упирались в контекст.
  2. Модель отвечает → текст печатается, вызовы инструментов идут в
     диспетчер, `finish` завершает задачу.
  3. Если модель вернула пустой ответ без вызовов три раза подряд — цикл
     останавливается с предупреждением.
  4. Системный промпт объясняет только *как* исследовать страницу (порядок:
     `list_regions` → `list_elements`/`read_text` → действие → проверка), но
     не что именно нажимать — это агент решает сам.

### Саб-агент страницы

- **`agent/subagent.py`** — специализированный саб-агент, который смотрит на
  страницу целиком и коротко (1-3 предложения) отвечает на один конкретный
  вопрос: «форма отправилась?», «есть ли ошибка валидации?», «что сейчас в
  модалке?».
  - На **Anthropic** саб-агент получает **скриншот** страницы (vision) плюс
    текст диалога и общий текст страницы.
  - На **Groq** (текстовые модели) используется fallback — только текст.
  Вызывается из основного цикла через инструмент `ask_page`. Это и есть
  паттерн «sub-agent architecture» из задания, он же экономит контекст
  основного цикла (1-3 предложения вместо 2-4 тысяч символов `list_elements`).

### Безопасность

- **`safety/confirm.py`** — перед необратимыми действиями (оплата, удаление,
  отписка, отправка заказа и т.п. — по списку `DANGEROUS_WORDS`) спрашивает
  подтверждение в терминале. Проверка идёт по тексту элемента, который
  диспетчер достаёт из `_last_elements`.

### CLI и логи

- **`cli.py`** — REPL на `rich`: постоянная сессия браузера, история задач
  между командами, команды `/help`, `/url`, `/new`, `/exit`. Проверяет, что
  ключ провайдера задан, при старте печатает активную модель и профиль.
- **`logging_utils.py`** — баннер, шаги, «модель думает», панель ответа,
  вызовы и результаты инструментов, предупреждения, итог, диалоговые
  сообщения браузера.
- **`main.py`** — минимальная точка входа (одна задача → выход); основной
  сценарий — через `cli.py`.

## Продвинутые паттерны

- **Sub-agent architecture** — `ask_page` делегирует понимание состояния
  страницы отдельному агенту, а не заставляет основной цикл разгребать
  сырой DOM.
- **Vision** — на Anthropic саб-агент видит скриншот, что позволяет ловить
  визуальные проблемы (пустые обязательные поля, ошибки под формой, «страница
  не та»), недоступные тексту.
- **Security layer** — подтверждение перед деструктивными действиями.
- **Self-healing / error-recovery** — повтор `list_elements`/`list_regions`
  при пустом результате сразу после навигации (SPA-гонка); действия не
  глотают исключения, а возвращают модели текст ошибки, чтобы она сменила
  подход; `click`/`type_text` прикладывают к результату ARIA-алерты; цикл
  ловит «модель упорно молчит» и останавливается сам.
- **Context management** — усечение старых `tool_result` и мягкое лимитирование
  истории, чтобы длинные задачи не упирались в окно модели.
- **Multi-provider** — Anthropic и Groq (OpenAI-совместимый API) через единый
  `ask_model`, с автоматической трансляцией форматов сообщений и инструментов.

## Известные ограничения / что дальше

- Vision-режим доступен только на Anthropic. На Groq сложные визуальные
  лейауты и капчи текстовым описанием элементов не покрываются.
- Cookie-баннеры и подобные попапы не обрабатываются специально — агент
  сам находит и закрывает их обычным `click`, чтобы не хардкодить логику
  под конкретные сайты.
- Саб-агент получает ограниченный контекст (один скриншот, до 1800 символов
  текста страницы, до 2000 символов текста диалога) — на очень больших
  страницах он видит только то, что попало в вьюпорт и в срез текста.
- Один основной агент на задачу; саб-агент — только для вопросов о состоянии
  страницы, произвольные подзадачи он не решает.
